# 节点创建文字规范（create.P1）

> 配套 `自定义节点创建规范.create.P0`（JSON/JS 结构范式）。本文管"怎么写字"：命名与文字层面的标准。**为什么要管这些？** 本次实践中的三个真实 bug 都能在"命名与文字"层面提前预防：
> - 端口输入/输出**同名** → 画布连线锚点错位（fact_deduper/source_scorer 踩坑）；
> - systemPrompt **没写输出边界** → 思考过程混入输出、污染下游；
> - 用 systemPrompt 覆盖区分行为 + 端口**语义过载** → 初稿/二稿/评审意见挤进同一个 `facts` 口。

---

## 1. `name` 标识符规范

- 硬性：小写英文 + 下划线（`^[a-z][a-z0-9_]*$`），create.P0 强制。
- 语义：**动作 + 对象**（动词开头），一眼看出"干什么、对什么干"。

| 准则 | 反例 ❌ | 正例 ✅ |
|---|---|---|
| 动作+对象 | `facts`（名词，像端口名） | `fact_extractor`、`source_scorer` |
| 不用无注释缩写 | `fe`、`qs` | `fact_extractor`、`query_splitter` |
| 不用复数 | `facts_extractor` | `fact_extractor` |
| 不与内置冲突 | `agent`、`output` | 自定义专用名 |
| 行为不同就换名 | `reporter` 干二稿的活 | 拆成独立类型 `reviser` |

**关键原则**：行为差异 → 新节点类型，禁止靠 systemPrompt 覆盖区分（否则只看类型会误判，人机都难读）。

## 2. 端口命名规范（重点：预防同名 bug）

### 2.1 输入口与输出口禁止同名
这是本次最痛的教训。画布渲染时按 `data-port` 匹配 socket，**同名时 `querySelector` 命中先渲染的输入口**，导致输出连线锚定到输入口位置。

| | 输入口 | 输出口 |
|---|---|---|
| ❌ 同名言 | `facts` | `facts` |
| ✅ 语义区分 | `facts` | `facts_merged` / `facts_scored` |

命名规则：**输入口用"进来的内容角色"，输出口用"加工后的结果角色"**，用动词过去式/形容词后缀体现"已被处理"。

### 2.2 端口名要带阶段语义，不要从头到尾都叫一个名
数据在流水线里每经过一站含义就变了，端口名应该跟着变，才能一眼看出"此刻装的是什么"：

```
content → facts → facts_merged → facts_scored
(正文)  (抽取)   (去重后)      (打分后)
```

### 2.3 格式
- 端口名：snake_case 英文名词短语（`draft`、`verdict`、`facts_merged`）
- 可选端口：label 标注 `(可选)`，并让 JS/提示词有兜底（如"无输入则输出 []"）
- 多输入/输出节点：每个端口职责唯一，禁止"一个口装两样东西"（如初稿+评审意见挤进 facts——已用 reviser 的 draft/verdict 口修正）

## 3. `label` / 画布 `title` 规范

- `label`：人类可读中文，简短（≤ 8 字），如 `事实抽取`、`来源打分`、`修订成稿`。
- 画布 `title`：`label` + 场景后缀区分多实例，如 `事实抽取·网页` / `事实抽取·本地素材`。
- **同类节点的多个实例靠 title 区分**；行为真正不同 → 拆类型（见 §1）。

## 4. `description` 规范

一句话说清：**输入什么 → 做什么 → 输出什么**，并注明是否耗 LLM。

```
✅ 事实抽取：从正文提取结构化事实条目（断言/数据/来源/置信度），强制只输出 JSON 数组，杜绝过程叙述混入。（智能体节点）
✅ 网页抓取：纯函数节点：输入 URL 列表，抓取网页并抽取正文文本（不耗 LLM，可配 maxPages/maxChars）。（函数节点）
```

函数节点应在 description 里注明 config 字段含义。

## 5. `systemPrompt` 写作规范（智能体节点）

### 5.1 必须写"输出边界"（防污染）
明确限定输出的唯一形态，杜绝思考过程/工具调用记录混入：

```
只输出一个 JSON 数组，不要输出任何其他文字、思考过程或解释。
只输出报告正文，不要输出思考过程或工具调用记录。
```

### 5.2 结构化输出优先 + 给 schema
要 JSON 就给字段定义；要 Markdown 就给定结构：

```
每条格式：{"claim":"断言","data":"数值","unit":"单位(可空)","source":"来源","date":"日期(可空)","confidence":0-1}
```

### 5.3 数量/长度约束
给上限防发散：`提取 3-8 条`、`输出 400 字以内`、`分条列出`。

### 5.4 单一职责
一个智能体节点只做一件事：抽取只抽取、核验只核验、成稿只成稿。职责混叠 → 拆节点。

### 5.5 tools 白名单必须配套
提示词里说"用 read 读文件" → tools 里要有 `"read"`；说"curl 检索" → tools 里要有 `"bash"`。提示词与工具不一致是最常见的运行失败源。

### 5.6 兜底指令
失败/空输入时的默认行为要写明：`无法提取则输出 []`、`被拦截则注明并给出知识推测（标注来源）`。

### 5.7 联网检索配方化
需要真实上网时，把可复用的命令直接写进提示词（UA、编码、解析方式、反爬兜底），别让模型自由发挥导致被拦截后瞎编。

## 6. JS 实现规范（函数节点）

- 返回对象的 key **必须**与 outputs 端口名一致（create.P0 强制）。
- 多边进同一口：引擎可能把多路值传成**数组**，用 `Array.isArray(inputs.x)` 兼容。
- 输入容错：text 前后可能带杂文本，解析 JSON 用"取首个 `[` 到末尾 `]`"再 try/catch，失败降级（如按行切）。
- 数值保护：上限/下限用 `Math.max/Math.min` 钳制（`maxPages≥1`、boost 不得为负）。
- 纯函数：不耗 LLM、无副作用、可重复执行。
- 写 `ctx.log` 便于画布调试。

## 7. 文档命名规范（nodes-docs）

- 文件名：`<文档名>.<分类>.<重要级>.md`
  - 分类：`core`（核心架构）/ `create`（创建规范）/ `guide`（使用指南）/ `reference`（参考）/ `example`（示例）/ `preset`（预设说明）
  - 重要级：`P0`（核心必读）/ `P1`（重要）/ `P2`（普通）/ `P3`（进阶可选）
- frontmatter 必须有 `title / description / tags`（tags 供检索）。
- 同一文档同步维护 `~/.pi/nodes-docs/` 与项目 `nodes-docs/` 两份。

## 8. 新增/修改节点检查清单

创建或修改节点前逐条对照：

- [ ] `name` 合法（小写+下划线）且表意（动作+对象）
- [ ] **输入口与输出口无同名**
- [ ] 端口名带阶段语义（`facts_merged` 而非全程 `facts`）
- [ ] 端口 type 来自类型注册表（text/image/file/path/any）
- [ ] 智能体节点：systemPrompt 含输出边界 + 数量约束 + tools 配套 + 兜底
- [ ] 函数节点：implementation 存在（`export default`）+ 输入容错 + 数值保护
- [ ] 联网节点：检索配方已写入提示词
- [ ] 行为差异已拆为独立类型，未用 systemPrompt 覆盖
- [ ] label/description 已写（描述里注明是否耗 LLM）

## 9. 本次实践教训（附录：这些 bug 都源于"文字不规范"）

| 问题 | 表象 | 规范层面的解法 |
|---|---|---|
| 输入/输出端口同名 | 输出连线锚定到输入口（画布渲染 bug） | §2.1 禁止同名 |
| systemPrompt 无输出边界 | 思考过程/工具记录混入输出、污染下游 | §5.1 强制输出边界 |
| 端口语义过载 | 初稿+评审意见挤进一个 `facts` 口 | §2.3 端口职责唯一 |
| systemPrompt 覆盖改行为 | `reporter` 干二稿的活，只看类型会误判 | §1 行为不同就拆类型 |
| 来源计数重复/打分负值 | 函数节点数字 bug | §6 数值保护 + 冒烟测试 |
