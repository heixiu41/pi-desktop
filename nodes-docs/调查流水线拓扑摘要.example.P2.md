## 三、数据流

- `topic/plan`：题目 → 拆解计划（text）
- `query/results`：关键词 → 检索结果（标题|URL|摘要）
- `urls/content`：URL列表 → 网页正文（**page_fetcher.urls 已由 path 修正为 text**）
- `facts → facts_merged → facts_scored`：结构化事实 JSON 的阶段链（端口名随阶段变化）
  - 抽取 `facts`：`[{claim,data,unit,source,date,confidence}]`
  - 去重 `facts_merged`：+ `supportedBy/sources`（支撑来源计数，已修复重复计数）
  - 打分 `facts_scored`：+ `score/scoreBasis`（可信度，已修复 boost 负值）
- `validation`：交叉核验报告独立进入成稿（不再挤进 facts 口）
- `draft→verdict`：初稿与评审意见**分端口**进入修订（reviser）

## 四、质量闭环说明

- 修订节点已独立为 `reviser` 类型（输入 draft/verdict/facts_scored），行为由类型表达而非 systemPrompt 覆盖。
- 评审为「软门」：reviser 始终运行但会按评审意见自适应（通过→精修，返工→大改）。如需「硬门」跳过二稿，需额外加选路函数节点。
