# 蓝图与预设说明（preset.P2）

内置三套预设，可直接加载运行，也可作为 AI 创建新蓝图时的参考模板。

## 1. 规划→执行→审查链（plan-execute-review）

```
input → planner(agent: 制定实施计划) → worker(agent: 按计划执行) → reviewer(agent: 审查结果) → output
```

- 串行链式结构：每步依赖上一步
- 适用：明确的开发/实现任务，要求质量闭环
- 关键点：planner 的输出（计划文本）作为 worker 的输入

## 2. 并行调研（parallel-research）

```
input(研究问题)
  ├→ researcher A(agent: 从角度 A 调研) ─┐
  ├→ researcher B(agent: 从角度 B 调研) ─┼→ output(合并汇总)
  └→ researcher C(agent: 从角度 C 调研) ─┘
```

- 并行结构：多个 worker 同时接收同一输入，各自独立研究
- output 节点合并所有结果
- 适用：开放性问题、多角度调研、对比分析

## 3. 代码审查流水线（code-review）

```
input(代码路径) → analyzer(agent: 静态审查) → fixer(agent: 给出修复方案) → output
```

- 串行：先审查发现问题，再产出修复建议
- 适用：代码质量检查、重构建议

## 蓝图 JSON 结构（AI 创建蓝图时参考）

```json
{
  "id": "blueprint-xxx",
  "name": "蓝图名称",
  "description": "任务描述/全局目标",
  "nodes": [
    { "id": "n1", "type": "input", "title": "输入", "x": 0, "y": 0,
      "config": { "content": "初始任务文本" } },
    { "id": "n2", "type": "agent", "title": "规划者", "x": 300, "y": 0,
      "config": { "systemPrompt": "你是规划者……", "model": null,
                  "thinkingLevel": "medium", "maxContext": 64000 } }
  ],
  "edges": [
    { "id": "e1", "from": "n1", "fromPort": "out", "to": "n2", "toPort": "context" }
  ],
  "version": 1
}
```

- 节点 id 以 `n` 开头；边 id 以 `e` 开头
- agent 节点输入端口：`context`（主输入）、`files`（文件路径列表）；输出端口：`text`
- input 节点：端口 `out`
- output 节点：输入端口 `in`（可多路接入）
