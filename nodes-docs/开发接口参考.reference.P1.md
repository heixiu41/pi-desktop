# 开发接口参考（reference.P1）

> 驱动画布/应用前先读本文，避免逐参数试错。

## 1. window.pi.* 系列（渲染进程可用，均通过 preload 暴露）

### 节点画布
| 方法 | 参数 | 返回 |
|------|------|------|
| `nodeOpen()` | 无 | 打开画布窗口 |
| `nodeReady()` | 无 | 通知主进程画布就绪 |
| `nodeGetState()` | 无 | `{presets:[], saved:[], nodes:[], blueprintsDir}` |
| `nodeSave(blueprint)` | 完整蓝图对象 | `{ok, blueprint}` |
| `nodeLoad(id, preset?)` | **字符串 id**（preset 为 true 表示预设） | `{ok, blueprint}` |
| `nodeDelete(id)` | 字符串 id | `{ok}` |
| `nodeRun(blueprint, selection?, wait?)` | **完整蓝图对象**；selection=节点id数组（调试）；wait=true 时**等待完成** | 非 wait：`{ok, runId}`；wait：`{ok, runId, status, results(按标题), resultsById(按节点id)}` |
| `nodeAbort(runId)` | 字符串 | 中止运行 |
| `nodeGetRun(runId)` | **字符串 runId** | `{found, status, name, error, nodes, resultsById}`；未找到 `{found:false,error}` |
| `homeGetRuns()` | 无 | `{runs:[{runId,name,done,total,nodes}]}` 进行中的运行 |

### 蓝图对象结构（nodeRun/nodeSave 的 blueprint 参数）
```json
{
  "id": "可选，字符串",
  "name": "蓝图名",
  "nodes": [{ "id": "n1", "type": "input|output|agent|retrieve|conference|自定义", "title": "...", "x": 0, "y": 0, "config": { } }],
  "edges": [{ "id": "e1", "from": "n1", "fromPort": "out", "to": "n2", "toPort": "context" }],
  "version": 1
}
```
- agent 输入端口：`context`(any)、`files`(file)；输出：`text`。配置见 3.2
- retrieve：输入 `query`，输出 `result`，config.k=返回条数
- conference：输入 `topic`，输出 `transcript`
- input：输出 `out`（config.content 为文本或 {type:'path',path}）
- output：输入 `in`（可多路）

### 其它
- `getState()` → `{cwd, modelName, thinkingLevel, isStreaming, sessionFile, messages}`
- `send(text)` / `abort()` / `newSession()` / `pickCwd()`
- `dl*`（下载管理）：`dlList/dlAdd(opts)/dlPause/dlResume/dlStop/dlRetry/dlOpenFolder/dlPickDest`
- `kb*`（知识库）：`kbList/kbStatus/kbImportFile(path)/kbImportText(name,text)/kbDelete(id)/kbSearch(query,k)/kbPickFile`
- `getHistory()` → `{sessions, archived}`；`loadSession(path)`（归档会话会自动恢复再加载）
- `summaryGetState/summarySetConfig/summaryRunNow/summaryDelete`
- `onEvent(channel, cb)` 订阅事件：`session:*`、`download:*`、`kb:*`、`home:runs`、`node:*`（node:event/node:init/node:run-started）

## 2. 开发遥控通道（外部驱动，无需重启）

主进程每 600ms 轮询 `~/.pi/dev-cmd.jsonl`（JSONL 追加），执行后把结果追加到 `~/.pi/dev-result.jsonl`。

**请求**（每行一个）：
```json
{"id":"任意字符串","target":"main|canvas","code":"在目标窗口执行的 JS"}
```
- `main` = 主窗口渲染进程；`canvas` = 画布窗口渲染进程（未打开会报 `画布窗口未打开`）
- code 返回 Promise 会等待其 resolve；异常时结果带 `{"__error":"..."}`

**响应**：`~/.pi/dev-result.jsonl` 每行 `{"id":"同上","result":<JS 返回值>}`。用 id 关联请求/响应；轮询该文件直到出现你的 id 行。

**注意**：code 在渲染进程执行，**无 fs**，不能读本地文件；需要传数据时内联进 code 字符串（用 JSON.stringify 转义）。

## 3. window.__nodeApi（画布窗口内，代码建图）

| 方法 | 说明 |
|------|------|
| `newGraph(name?)` | 清空并新建蓝图（重置创建动画） |
| `addNode(type, x, y, config)` | 返回新节点 id（如 "n6"） |
| `setTitle(id, title)` / `configNode(id, patch)` / `setInput(id, text)` | 配置节点 |
| `addEdge(from, fromPort, to, toPort)` | 建连线，返回是否成功（允许多路合并） |
| `getGraph()` | 返回当前蓝图对象 |
| `runAndWait(timeoutMs?)` | 运行并等待完成，返回每节点 `{id,type,title,status,output,error}` |

## 4. 关键错误排查
- `nodeRun` 报错：确认传的是**完整蓝图对象**（nodes 数组不能为空/undefined）
- `画布窗口未打开`：先 `nodeOpen()` 再操作 canvas 目标
- `nodeGetRun` 返回 found:false：runId 拼写错误或运行已过久
- 智能体输出边界：默认输出=最终回复文本；但**实测部分模型会把思考过程/工具调用叙述写进输出**（本项目中 n3 曾出现"我来按规范逐组检索…"混入输出，污染下游），因此智能体节点必须在 systemPrompt 显式声明输出边界（见 `节点创建文字规范.create.P1`），或用 `fact_extractor` 这类强制结构化输出的节点兜底；开启传导模式后输出=完整记录+本轮发言

## 5. 数据流类型
`text / image / file / path / any`（可扩展）。连线要求输出类型与输入类型一致或任一方为 any。

## 6. 状态同步规则（重点，易踩坑）
- **main 的 `nodeLoad(id)` 只把蓝图读进主进程，不会推送到画布窗口**。画布窗口是独立渲染进程，持有自己的图。
- 驱动画布显示新蓝图的方式：
  1. 画布窗口内调 `window.__nodeApi.reloadNodes()` 刷新节点定义；
  2. 用 `__nodeApi.newGraph(name)` + `addNode(type,x,y,config)` + `addEdge(from,fromPort,to,toPort)` **重建**（addNode 自动分配 id：n1,n2,…，需用返回的 id 记映射）；
  3. 或让用户在画布 UI 的「加载」下拉里选蓝图。
- `addNode(type, x, y, config)` 的参数顺序是 type→x→y→config；id 不能自定义。
- 多窗口并发：你重建画布图的同时若用户在画布上拖动节点，会互相覆盖（无版本冲突检测）。

## 7. 节点库热加载链路
修改 `~/.pi/nodes/*.json` 或 `*.js` 后，必须依次：
1. 主进程：`window.pi.nodeReload()` → `{ok, count, nodes:[...]}`
2. 画布窗口：`window.__nodeApi.reloadNodes()`（内部会再调 nodeReload 并刷新 registry）
3. 再重建/重载蓝图，否则画布仍用旧端口定义。

## 8. 已知引擎行为（实测）
- **多边进同一输入口**：引擎把多路值作为**数组**传给 JS 的 `inputs[port]`，函数节点需用 `Array.isArray()` 兼容；智能体节点则按 `### 输入「端口名」` 分组拼接为一条用户消息。
- **同名输入/输出端口**曾导致画布连线锚点错位（`sockPos` 按 `data-port` 匹配命中先渲染的输入口）——已在 `renderer/canvas.js` 修复（sockPos 增加 kind 参数）；**新节点应避免同名端口**（见 create.P1 §2.1）。
- `nodeRun(bp, null, true)` 的 wait 模式**实测有效**：返回 `{ok, runId, status, results}`，results 按**节点标题**索引。

## 9. 函数节点单测口径
不经画布直接测任意函数节点（避免为验证一个小改动而搭临时蓝图）：
```
node node-test.mjs --all                                          # 冒烟全部函数节点
node node-test.mjs fact_deduper --inputs '{"facts":"[...]"}'    # 单测指定节点
```
脚本位置：`<项目>/node-test.mjs`；校验返回值 key 与声明的 outputs 一致，退出码 0/1 可接 CI。
