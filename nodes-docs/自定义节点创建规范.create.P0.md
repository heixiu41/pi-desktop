# 自定义节点创建规范（create.P0）

## 1. 标准范式：双轨制

每个自定义节点 = **JSON 声明**（必须）+ **JS 实现**（可选）。

- 只有 JSON 声明（无 JS 实现）→ 该节点作为**智能体节点**运行：系统提示词取自声明的 `systemPrompt`，输入内容作为用户消息。
- 带 JS 实现 → 该节点作为**函数节点**运行：直接调用实现函数，不消耗 LLM。

## 2. JSON 声明格式

文件：`~/.pi/nodes/<name>.json`（或 `<项目>/.pi/nodes/<name>.json`）

```json
{
  "name": "translate_agent",
  "label": "翻译智能体",
  "description": "把输入文本翻译成目标语言",
  "category": "agent",
  "inputs": [
    { "name": "text", "type": "text", "label": "待翻译文本" }
  ],
  "outputs": [
    { "name": "text", "type": "text", "label": "译文" }
  ],
  "systemPrompt": "你是专业翻译。把输入文本翻译成英文，只输出译文。",
  "tools": ["read"],
  "implementation": "translate_agent.js"
}
```

字段规则：
- `name`：唯一标识，**小写英文 + 下划线**（正则 `^[a-z][a-z0-9_]*$`）
- `inputs` / `outputs`：端口数组，每个端口 `{ name, type, label? }`；type 必须来自类型注册表（text/image/file/path/any）
- `systemPrompt`：可选；无 JS 实现时作为智能体节点的系统提示词
- `tools`：可选；智能体节点允许的工具白名单（默认 read/bash/edit/write/download）
- `implementation`：可选；JS 实现文件名（与 JSON 同目录）

## 3. JS 实现格式

文件：`~/.pi/nodes/<name>.js`（与 JSON 同目录同名）

```js
// 默认导出对象，execute 为入口
export default {
  async execute(inputs, config, ctx) {
    // inputs:  { 端口名: { type, text?, path? } }
    // config:  节点配置面板里用户填写的额外配置
    // ctx:     运行上下文 { run, node, log(text) }
    // 返回：    { 输出端口名: { type, text } } 或 { 输出端口名: "字符串" }
    const text = inputs.text?.text || "";
    return { text: { type: "text", text: text.toUpperCase() } };
  },
};
```

注意：
- 必须是 ES Module（`export default`）
- execute 可以 async；内部可调用任意 Node API
- 返回对象的 key 必须与声明的 outputs 端口名一致

## 4. 创建步骤（AI 必读）

1. 先读取本文件（create.P0）和 `数据类型与配置参考.reference.P2.md`
2. 用 `view_node_library` 确认节点名不冲突
3. 用 `create_node` 工具创建（传入 name/label/description/inputs/outputs/systemPrompt/implementationCode）
4. 创建后用 `view_node_library` 验证已注册
5. 若节点行为不符合预期，用 create_node 同名覆盖更新（会重新加载）

## 5. 校验规则（create_node 强制执行）

- name 不合法 → 拒绝
- 端口名重复 / 端口 type 不在注册表 → 拒绝
- inputs 或 outputs 为空 → 拒绝
- implementationCode 存在且含 `export default` → 写 JS 文件，否则拒绝
